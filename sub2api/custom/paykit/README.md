## 站内导航入口（已配置）

sub2api 的 `settings.custom_menu_items` 里加了两项，按角色显示：

| 菜单 | 谁看得到 | 指向 |
| --- | --- | --- |
| **Recharge** | 普通用户 | `https://www.hacket.top/pay/` |
| **Payment Setup** | 管理员 | `https://www.hacket.top/pay/admin` |

图标用 `icon_svg` 字段（与内置菜单同款 stroke 风格）：
用户项是信用卡图标，管理项是齿轮图标。

> ⚠️ sub2api 的自定义菜单**只有一个 `label` 字段，没有多语言字段**（后端 `dto.CustomMenuItem` 只有
> `id / label / icon_svg / url / page_slug / visibility / sort_order`）。
> 所以没法做到"英文界面显示英文、中文界面显示中文"。当前按站点界面语言（英文）配成英文；
> 若要中文界面，把 label 改成「充值 / 收款配置」即可，或者需要自建镜像改后端给它加 i18n 字段。

> 用数据库直接改 `custom_menu_items`（JSON 数组），**不要**走 `PUT /api/v1/admin/settings` ——
> 那个接口的 `UpdateSettingsRequest` 里很多字段是非指针 bool，局部提交会把注册开关等一起冲成 false。

## 套餐后台可编辑（价格自拟，按时长开通）

后台第二块「套餐（价格 / 天数）」，每行可改：

| 字段 | 说明 |
| --- | --- |
| 名称 / 徽标 | 卡片标题与小标签 |
| **价格** | 随便定，前端卡片就显示这个价 |
| **天数** | 才是用户实际拿到的权益（1=日卡、7=周卡、30=月卡、14=两周…） |
| 描述 / 权益 | 卡片副标题和 ✓ 列表（逗号分隔） |
| 分组 ID | 开通到哪个分组（当前 8888ok官转 = 5） |

改完点「保存套餐」立即生效（存 `kv.site_plans`，优先于 `paykit.json`）。
`+ 新增一档` 可以加任意档位，`删` 去掉。

实测（2026-11-12）：

| 操作 | 结果 |
| --- | --- |
| 日卡价格 10 → 12 | 前端立即显示 `CNY 12 / 1 天` ✅ |
| 再改回 10 | 前端恢复 `CNY 10 / 1 天` ✅ |
| 当前默认 | 日卡 ¥10（1 天）/ 周卡 ¥50（7 天）/ 月卡 ¥150（30 天） |

固定档位下拉的候选金额（默认）：`1, 2, 5, 10, 20, 30, 50, 70, 100, 120, 150, 200`（外加套餐价）。

## 收款方式：两种模式（后台可切）

后台第一块「收款方式」，保存立即生效（前端展示 + 后端校验同时改）：

| 模式 | 用户端 | 用哪种收款码 | 后端校验 |
| --- | --- | --- | --- |
| **允许自定义金额** | 只有金额输入框，**不显示任何档位** | 只用「通用（不限额）」码 | 任意 >0 金额 |
| **仅固定档位** | 只有档位按钮（下拉多选出来的金额） | 优先该金额的定额码 | 金额必须命中档位，否则 400 |

- 固定档位用**下拉多选**（选项含常用金额 + 套餐价 + 已保存值），不用再手打逗号串
- **套餐卡片的价格不受此设置影响**，始终按卡片价收款
- 自定义模式下如果没有通用码，后台覆盖检查会红字提示「缺，需上传不限额码」

## 二维码下方一定会说明是哪种码

| 码的类型 | 订单页提示 |
| --- | --- |
| 定额码（绑定金额 > 0） | 「这是 **CNY 10 的定额收款码**，扫码后直接付 CNY 10 即可」 |
| 通用码（绑定 0） | 「这是 **自定义金额收款码**，扫码后请输入 CNY 9.90」 |
| 定额码金额 ≠ 订单金额 | 顶部红字「定额码金额与订单金额不一致，请联系客服」 |

**多张通用码时，用户可以在订单页点按钮切换用哪一张**（只影响展示，管理员看到的仍是订单派定的那张）。

## 收款码可以绑定金额（定额码按档位自动切换）

支付宝的**定额收款码**（比如 ¥10.00 那种）只能收固定金额，所以每张码可以绑一个金额：

| 绑定金额 | 含义 | 派单规则 |
| --- | --- | --- |
| `10` | ¥10 定额码 | 订单金额 = 10 时优先用它 |
| `0` / 留空 | 通用码（不限额） | 没有精确匹配时用它 |

**下单时的选择顺序**：`金额完全匹配的定额码` → `通用码` → `兜底用启用码（会红字告警）`。

后台每张码下面有「绑定金额」**下拉选择**（`通用（不限额）` / `1,2,5,10,20,30,50,70,100,120,150,200` / 套餐价），选完点「绑定」立即生效。
「固定档位」也是**复选下拉**（点开勾选，收起后显示已选金额），不再是输入框。

```
套餐价： 套餐 CNY 9.9 ✓   套餐 CNY 49 ✓   套餐 CNY 159 ✓
自定义金额： 通用收款码 1 张 ✓          ← 固定档位模式则显示「充值档位：...」
```

实测（2026-11-12）：

| 场景 | 结果 |
| --- | --- |
| 自定义模式 + 2 张通用码，下 ¥9.9 | 订单页出现 2 个可切换按钮，提示「这是自定义金额收款码」✅ |
| 只有 ¥10 定额码，下 ¥9.9 | 兜底该码 + 红字不一致告警 ✅ |
| 只有 ¥10 定额码，下 ¥10 | 命中定额码，提示「直接付 CNY 10」✅ |

> 建议：卖多档（9.9 / 49 / 159）时，要么各传一张定额码并绑定对应金额，
> 要么传一张**不设定额**的收款码并绑定 0（推荐，最省事）。

## 收款方式（旧版说明，已合并到上面）

后台首页第一块「收款方式」：

| 选项 | 用户看到 | 后端校验 |
| --- | --- | --- |
| **允许自定义金额** | 快捷档位按钮 + 自由输入框 | 任意 `>0` 金额 |
| **仅固定档位** | 只有档位按钮（无输入框） | 金额必须命中 `amount_presets`，否则 400 拒绝 |

档位在同一处用逗号分隔编辑（如 `10,50,100,200`），保存后**立即生效**，不需要重启。
开关存 `paykit.db` 的 `kv` 表（`allow_custom_amount` / `amount_presets`），优先级高于 `paykit.json`。

> 为什么要后端也拦：只改前端的话，用户直接 POST `/pay/create` 就能绕过；所以服务端对
> 「仅固定档位」模式做了白名单校验。

## 使用流程

### 管理员（一次性配置）

1. 打开 https://www.hacket.top/pay/admin → 输入账号口令登录
2. 「支付宝收款码」区块 → 选择图片（支付宝 App → 收钱 → 保存收款码）→ 填备注名 → 点「上传」
3. 可重复上传多张；每张都能**停用/启用/删除**
4. 新订单会自动分配给「当前待处理订单最少」的那张启用码

### 日常（每笔五分钟内）

1. 用户下单 → 拿到备注码 `666-XXXXXX` → 扫码转账并在备注里写这个码
2. 你在支付宝看到到账 → 打开 `/pay/admin` → 找到对应订单 → 点「**确认到账**」
3. 系统自动调 sub2api `create-and-redeem`：套餐单开通订阅、充值单加余额（**幂等**，重复点不会重复加）
4. 邮箱匹配不到用户时，自动生成兑换码显示在结果页，复制发给用户即可

## 为什么不是全自动

个人支付宝收款码**没有回调能力** —— 钱进的是你个人账户，支付宝不会通知任何服务器。
所以「确认到账」必须人工点一次；点完之后的开通是全自动的。

想要真回调只有三条路：支付宝官方当面付（需个体户/营业执照）、第三方聚合（XPAY 等）、
挂手机监听（V免签类，掉单/封号风险）。详见 `../XPAY.md`。

## 配置

编辑 `/root/cpaproxy/sub2api/paykit/paykit.json` 后 `systemctl restart paykit`：

```json
{
  "site_name": "666ok",
  "admin_email": "admin@hacket.top",        // sub2api 管理员邮箱（用于调管理 API）
  "admin_password": "<sub2api 管理员密码>",
  "admin_user": "admin",                     // 本台登录账号
  "admin_pass": "<本台登录口令>",
  "payee_note": "转账时请在备注里填写下方「备注码」",
  "amount_presets": [10, 50, 100, 200],
  "plans": [
    { "label": "DeepSeek 日卡", "badge": "日卡", "days": 1,  "amount": 9.9,  "group_id": 5,
      "desc": "1 天无限量 · 支持 v4 / v4.1 flash / pro", "features": ["无限流量", "全部分组"] },
    { "label": "DeepSeek 周卡", "badge": "周卡", "days": 7,  "amount": 49,   "group_id": 5 },
    { "label": "DeepSeek 月卡", "badge": "月卡", "days": 30, "amount": 159,  "group_id": 5 }
  ]
}
```

- `days > 0` → 开通订阅（`subscription` 兑换码，绑定 `group_id`）
- `days = 0` → 加余额（`balance` 兑换码，值 = 订单金额）
- `features` 会渲染成卡片上的 ✓ 列表，`desc` 是卡片描述

## 与 sub2api 自带「充值/购买」页的关系

sub2api 自带的 `/purchase` 页显示 *Top-up is currently unavailable*，是因为它没有配置**支付通道 provider**
（需要 EasyPay/支付宝/Stripe 等真实通道）。我们用的是 paykit，所以那个页面对用户没有意义，
充值入口请直接指向 `https://www.hacket.top/pay/`。
